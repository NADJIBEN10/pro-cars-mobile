🚗 iQ Cars — Complete Technical Documentation
A comprehensive blueprint of the iQ Cars web platform, prepared so another AI (Replit AI) can rebuild it as a production-ready React Native + Expo mobile app.

1. Project Overview
Name: iQ Cars Type: Automotive marketplace (web app, built on TanStack Start). Tagline: "Iraq & Kurdistan's largest car marketplace."

Main idea: A trilingual (English / Arabic / Kurdish) marketplace where private sellers and dealers list vehicles, and buyers can search, compare, save, chat with sellers, and read editorial content (guides, news, videos).

Purpose / problems solved:

Fragmented car buying/selling market in Iraq & Kurdistan — no dominant trusted online hub.
Buyers can't easily filter thousands of listings, compare specs, or verify dealers.
Sellers (both private and 1,000+ showrooms) lack a professional listing platform.
Language barrier — supports EN / AR / KU with RTL layout.
Target users:

Buyers – browsing, filtering, saving, contacting sellers.
Private sellers – posting one-off vehicle listings.
Dealers / Showrooms – managing inventory, subscriptions, analytics.
Moderators / Admins – handling reports, verifying dealers.
Main features (delivered v1):

Multilingual UI with runtime language switch + RTL.
Hero + advanced search bar on the home page.
Popular cars, categories, brand grid, testimonial-style CTA sections.
Full advanced search page with faceted filters + sort.
Car detail page (gallery, specs, features, seller card, similar cars).
Compare cars side-by-side (up to N).
Sell Car multi-step wizard.
Auth (email/password + Google via Lovable Cloud broker).
Personal Dashboard (my listings, favorites) + Favorites/Watchlist.
Editorial pages: Guide, News, Videos.
Theme toggle (light/dark) + persistent language.
Toast notifications (sonner).
Business logic highlights:

Listings have lifecycle: draft → pending → active → sold/expired/rejected.
Sellers are private or dealer; dealers hold subscriptions (free/basic/pro/enterprise) that cap listing quota.
Prices stored in USD (price_usd) with optional IQD mirror.
Every price change is logged (car_price_history) via DB trigger.
Favorites, saved searches, conversations, messages, notifications, reports, dealer reviews all supported at the schema level.
Role model uses a separate user_roles table + has_role() security-definer function (no role columns on profiles — anti-privilege-escalation).

2.3 How it connects
server.ts → boots TanStack Start server entry on Cloudflare Workers.
start.ts → registers attachSupabaseAuth (adds bearer token to server-fn calls) + error middleware.
router.tsx → creates the router with a shared QueryClient.
routes/__root.tsx → wraps every page with <QueryClientProvider>, <I18nProvider>, <AuthProvider>, <Header>, <Outlet/>, <Footer/>, <Toaster/>, and a single supabase.auth.onAuthStateChange listener that invalidates the router + query cache on SIGNED_IN/OUT/USER_UPDATED.
Client Supabase calls go through @/integrations/supabase/client. Server calls use requireSupabaseAuth in server functions.

6.3 DB functions / triggers
handle_new_user() — trigger on auth.users: inserts a profiles row + default user_roles row.
has_role(uuid, app_role) — SECURITY DEFINER, checks membership without RLS recursion.
log_car_price_change() — trigger inserting car_price_history on insert/price update.
set_updated_at() — generic trigger for updated_at columns.
6.4 RLS summary
Read-only public: brands, car_models, categories, cities, car_images, car_videos, car_price_history, dealers, dealer_reviews, profiles.
cars: public SELECT only when status='active'; owner has full CRUD; admin/moderator override.
favorites, saved_searches, notifications, messages, conversations: strictly owner/participant scoped via auth.uid().
reports: users can create, only mods/admins can read.
user_roles: readable only by self; writes locked (roles assigned server-side).
6.5 Auth
Supabase Auth. Email/password + Google via Lovable OAuth broker.
Session in localStorage; bearer token attached to server fns by attachSupabaseAuth.
Signup trigger seeds profile + user role automatically.
6.6 Storage
Buckets to be created for car-images, dealer-logos, avatars (Storage panel — not yet provisioned in v1).
6.7 APIs
No custom edge functions — TanStack createServerFn handles server-side reads/writes with requireSupabaseAuth middleware.
External webhooks/cron would live under src/routes/api/public/*.

8. User Flows
Buyer

Land on / → scan hero, popular cars.
Use SearchBar or click category → /search?brand=….
Filter/sort results → click card → /car/:id.
Save to Watchlist (heart) → prompted to sign in if not authed.
Click Call/WhatsApp → device dial/WhatsApp intent. Click Message → creates conversation, opens chat.
Optionally: add to /compare (up to 3-4 cars).
Private seller

/auth → create account (auto profile + user role).
Click "Sell Car" → /sell wizard → steps 1-6 → submit.
Listing enters pending. After moderation → active.
Manage in /dashboard (edit price, mark sold, delete).
Dealer

Same signup, then requests dealer upgrade (admin sets dealer role + creates dealers row + subscriptions row).
Manages fleet from dealer dashboard (planned /dashboard/dealer).
Receives buyer messages, showcases profile at /dealer/:slug.
Admin / Moderator

Sign in → /admin (planned).
Review reports, approve/reject cars, verify dealers, view audit_logs.
OAuth flow

User taps "Continue with Google" → lovable.auth.signInWithOAuth("google", { redirect_uri: origin }).
Broker returns tokens → supabase.auth.setSession() → redirect /dashboard.
